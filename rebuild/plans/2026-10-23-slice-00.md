# Slice 00 „Scaffold“ – Implementierungsplan

> **Abweichungen vom Plan (Umsetzung 2026-10-23):** kein Verify (Sponsoring-Erklärung ab v33 nötig; Entscheidung User) → eigener `JsonSnapshot`-Vergleich, D14 angepasst; `AddMcpTimeServer` registriert einen leeren `ListToolsHandler`, weil ein Server ohne Tools die Fähigkeit `tools` sonst nicht anbietet (Slice 01 ersetzt ihn); Testnamen mit `Async`-Suffix (Benennungsregel); Protokolltest prüft `NegotiatedProtocolVersion`; Harness mit 30-s-Timeout und stderr-Mitschrift; `dotnet_diagnostic.IDE1006` als Warnung, damit Benennungsregeln im Build greifen.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine leere, lauffähige .NET-10-Solution mit allen Quality Gates (Warnungen als Fehler, Format, Architekturtests, CI auf drei Betriebssystemen) und einem Test-Harness, der „jetzt“ einfriert und den gebauten Server per stdio startet.

**Architecture:** Drei Projekte `McpTime.Core` → `McpTime.Server` → `McpTime.Host` (Pfeile = erlaubte Abhängigkeiten) plus drei Testprojekte. Der Host startet den Generic Host mit stdio-Transport und noch ohne Tools; der Server stellt die Registrierung `AddMcpTimeServer()` bereit. NetArchTest erzwingt die Abhängigkeitsrichtungen, eine Dateilängen-Regel die 300-Zeilen-Grenze.

**Tech Stack:** .NET 10 SDK 10.0.402, C# 14, `ModelContextProtocol` 2.3.0, `NodaTime` 3.3.6, `Microsoft.Extensions.Hosting` 10.0.13, `xunit.v3` 4.0.2 auf Microsoft.Testing.Platform, `Microsoft.Extensions.TimeProvider.Testing` 10.11.0, `Verify.XunitV3` 33.3.4, `NetArchTest.eNhancedEdition` 1.4.5, GitHub Actions.

**Spec:** `rebuild/slices/00-scaffold.md`, `CLAUDE.md` (Architecture, Hard rules), `rebuild/PRD.md` P1–P5, `rebuild/research.md` D1, D2, D11–D14, D16, D19, `rebuild/parity/README.md` (Harness).

## Review Focus

1. **Testprojekt referenziert ein Exe-Projekt**: `McpTime.Host.runtimeconfig.json` muss im Testausgabeordner liegen, sonst startet `dotnet McpTime.Host.dll` nicht → Task 4 prüft das mit einem eigenen Test auf die Datei.
2. **Trim-Analyzer gegen Generic Host**: `Host.CreateApplicationBuilder` oder `AddConsole` könnten IL2026/IL3050 melden und den Build rot machen → Task 1 baut mit `-warnaserror`; eine Warnung wird gemeldet, nicht unterdrückt.
3. **Leere Assemblies machen Architekturregeln vakuum-wahr**: Core und Server haben in Slice 00 fast keine Typen → Task 3 prüft zusätzlich, dass jede geprüfte Assembly geladen wurde (Regel läuft gegen echte Assemblies, nicht gegen `null`).
4. **Verify in der CI**: ohne `DiffEngine_Disabled=true` versucht Verify ein Diff-Werkzeug zu starten → Task 5 setzt die Variable im Workflow; `*.received.*` bleibt in `.gitignore`.
5. **`dotnet format` auf Windows (CRLF)**: `.editorconfig` legt **kein** `end_of_line` fest, `.gitattributes` normalisiert auf LF im Repo. Task 5 lässt `dotnet format --verify-no-changes` lokal (Windows) und in der CI (Linux) laufen.
