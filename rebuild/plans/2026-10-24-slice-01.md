> **Deviations from the plan (implementation 2026-10-24):** tasks 2 and 3 implemented in one pass; added descriptions for `source`/`target` in the conversion schema ("The given time in the source time zone." / "The same moment in the target time zone."); new server types are `internal`, only `AddMcpTimeServer` is public; `Assert.NotNull(ServerInfo)` because of nullability; task 4 fix round: a blocked stdout read can be canceled with `WaitAsync`, every stdout line is checked with its line number, `IsResponseWithId` ignores messages with `method`; snapshot written by hand and matched on the first run. > **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The stdio server calls itself `mcp-time`, speaks both protocol generations, and lists exactly `get_current_time` and `convert_time` with its own descriptions, input and output schemas and all four annotations – the tool bodies have no time logic yet.

**Architecture:** `McpTime.Server` describes the tools explicitly as subclasses of `McpServerTool` (schema and annotations as data, no reflection scan, D12) and registers them through `AddMcpTimeServer(localTimeZone)`; unknown tools, unknown methods and the negotiation of the protocol generation are handled by the SDK (D8). For now the host passes `"UTC"` as the local time zone (slice 04 replaces that with detection/`--local-timezone`). Protocol tests run the built server over stdio in both generations; a raw stdio test ensures that stdout contains only JSON-RPC (D16).

**Tech Stack:** .NET 10, `ModelContextProtocol` 2.3.0 (`McpServerTool`, `WithTools(IEnumerable<McpServerTool>)`, `McpServerOptions.ServerInfo`), `System.Text.Json.Nodes` for the schemas, xunit.v3 on MTP, harness `ServerUnderTest`/`JsonSnapshot` from slice 00.

**Spec:** `rebuild/slices/01-server-core.md`, `rebuild/PRD.md` F1 (AC1–AC5; AC5 only prepares the text, parity I-LIST-6 belongs to slice 04), `rebuild/parity/interface-cases.md` (I-INIT-1/2, I-LIST-1..5, I-LIST-7, I-ERR-1/2/4, I-LOG-1), `rebuild/research.md` D2, D7–D12, D16, `CLAUDE.md`.

## Global Constraints

- Dependencies only in the direction of the arrows: Host → Server → Core; `ModelContextProtocol` only in Host and Server; no new packages (CLAUDE.md).
- ≤ 300 lines per file, one responsibility per class, no dead code, no TODO; `dotnet build -warnaserror` and `dotnet format --verify-no-changes` green.
- Tool names `get_current_time`, `convert_time`; parameters `timezone` or `source_timezone`, `time`, `target_timezone`, optional `date`; result fields `timezone`, `datetime`, `day_of_week`, `is_dst` or `source`, `target`, `time_difference` (PRD P2, I-LIST-2..4).
- Annotations set explicitly per tool: readOnly true, destructive false, idempotent true, openWorld false (D9).
- Business errors are never `McpException`/`McpProtocolException` (D7); description texts are written from scratch, in English, and name the purpose, the formats and the local time zone as the default (PRD "API").
- stdout carries only JSON-RPC, logs go to stderr (D16); no `Console` in Core/Server (architecture test).
- One commit for the green slice – the tasks do not commit individually; before the commit, check the local Git identity `vompa <22331101+vompa@users.noreply.github.com>`.
- Microsoft C# naming: `Async` suffix, `_camelCase`/`s_camelCase`; file names in English.

## Assumptions (confirm on approval)

1. **Bodies without logic** return a `CallToolResult { IsError = true }` with the text `Tool '<name>' is not implemented yet.` – not a JSON-RPC error, so that I-ERR-4 ("call succeeds" = no protocol error) can already be checked; `isError: false` is checked by slice 02 (I-RES-1).
2. **Local time zone** is the fixed value `"UTC"` from the host in this slice; the server receives it as `string localTimeZone` and puts it into the parameter descriptions (prepares AC5). Slice 04 delivers the real value; the snapshot therefore says `UTC`.
3. **Version** comes from `<Version>0.1.0</Version>` in `Directory.Build.props` (InformationalVersion without `+commit`).
4. I-LOG-1 is already met by the scaffold server; the test is a regression guard and is not red when written.

## Review Focus

1. `tools/call` with `arguments: null` or without `arguments` → must not crash; the body returns `isError` (task 3, I-ERR-4 variant without arguments).
2. `initialize` twice, or `ping` in 2026-07-28 → the SDK answers -32601, the process does not crash (task 2, I-INIT-2).
3. `tools/list` in both generations must be byte-identical – no per-session state in the tool objects (task 1, equality test).
4. Descriptions with `'` or `/` (time zone names) must appear unchanged in the JSON – the snapshot uses `UnsafeRelaxedJsonEscaping`, clients see raw text (task 1, snapshot).
5. After stdin ends, the process must end on its own, otherwise tests and clients hang (task 4, raw stdio test waits for exit with a timeout).

Description texts (fixed, `{local}` = `localTimeZone`):

| Place | Text |
|---|---|
| `get_current_time` | `Returns the current date and time in an IANA time zone, including the UTC offset, the English weekday and whether daylight saving time is in effect.` |
| `timezone` | `IANA time zone name such as 'America/New_York' or 'Europe/London'. Use '{local}' (the server's local time zone) if the user does not name one.` |
| `convert_time` | `Converts a wall-clock time from one IANA time zone to another and reports the offset difference in hours. Handles daylight saving time, quarter-hour offsets and date boundaries.` |
| `source_timezone` | `IANA time zone the given time is in, such as 'Europe/Vienna'. Use '{local}' (the server's local time zone) if the user does not name a source time zone.` |
| `time` | `Time to convert in 24-hour HH:MM format, such as '14:30'.` |
| `target_timezone` | `IANA time zone to convert to, such as 'Asia/Tokyo'. Use '{local}' (the server's local time zone) if the user does not name a target time zone.` |
| `date` | `Optional date of the time to convert in YYYY-MM-DD format, such as '2024-03-10'. Defaults to today in the source time zone.` |
| Output `timezone` | `IANA time zone name exactly as requested.` |
| Output `datetime` | `ISO 8601 date and time with UTC offset, such as 2024-01-01T13:00:00+01:00.` |
| Output `day_of_week` | `English weekday name, such as Monday.` |
| Output `is_dst` | `True when daylight saving time is in effect at that moment.` |
| Output `time_difference` | `UTC offset of the target minus the source time zone in hours, such as +5.75h or -4.0h.` |
