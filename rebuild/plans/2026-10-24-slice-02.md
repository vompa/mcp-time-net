# Slice 02 „Zeitzonen & aktuelle Zeit“ – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `get_current_time` liefert für jede gültige IANA-Zeitzone die richtige aktuelle Zeit als `structuredContent` plus JSON-Textblock und lehnt fehlende, unbekannte, falsch geschriebene Namen und Pfade mit `isError` und klarem Text ab.

**Architecture:** `McpTime.Core` bekommt drei Typen: `TimeZoneName` (exakter Abgleich gegen `DateTimeZoneProviders.Tzdb.Ids`, D3/D4), `TimeResult` (Zeitpunkt-Ergebnis, ISO 8601 mit Offset auf Sekunden, englischer Wochentag, Sommerzeit-Flag) und `CurrentTime` („jetzt“ aus `TimeProvider`, D13). `McpTime.Server` liest das Argument roh (D10), baut Fachfehler selbst als `CallToolResult { IsError = true }` (D7) und serialisiert das Ergebnis über einen `JsonSerializerContext` mit snake_case (D11). Der Host übergibt `TimeProvider.System`.

**Tech Stack:** .NET 10, NodaTime 3.3.6 (`Tzdb.Ids`, `Instant.InZone`, `ZonedDateTime.IsDaylightSavingTime()`, `OffsetDateTimePattern`), `ModelContextProtocol` 2.3.0, System.Text.Json Source Generator, xunit.v3, `FakeTimeProvider` (Harness `FrozenClock` aus Slice 00).

**Spec:** `rebuild/slices/02-current-time.md`, `rebuild/PRD.md` F2 (AC1–AC5, unbekannte Argumente), `rebuild/parity/business-cases.md` (B-NOW-1..15, B-ERR-1..5), `rebuild/parity/interface-cases.md` (I-RES-1, I-ERR-3, I-ERR-4), `rebuild/research.md` D3, D4, D7, D10, D11, D13, `CLAUDE.md`.

## Global Constraints

- Abhängigkeiten nur Host → Server → Core; Core nur NodaTime, kein `TimeZoneInfo`, kein MCP-SDK, kein `Console` (Architekturtests); keine neuen Pakete.
- „Jetzt“ nur über `TimeProvider` – nie `DateTime.Now`, `DateTimeOffset.UtcNow`, `SystemClock` (D13).
- Ein Name ist nur gültig, wenn er ordinal in `DateTimeZoneProviders.Tzdb.Ids` steht; keine Normalisierung (kein Trim, keine Groß-/Kleinschreibung) (D4, P3).
- Fachfehler nur als selbst gebautes `CallToolResult { IsError = true }`, nie `McpException`/`McpProtocolException` (D7); Fehlertexte nennen Argument, Wert und erwartetes Format.
- JSON nur über `JsonSerializerContext` (D11); Ergebnisfelder exakt `timezone`, `datetime`, `day_of_week`, `is_dst` (P2).
- ≤ 300 Zeilen je Datei, eine Verantwortung je Klasse, kein toter Code, kein TODO; `dotnet build -warnaserror` und `dotnet format --verify-no-changes` grün.
- Benennung Microsoft C#: `Async`-Suffix, `_camelCase`/`s_camelCase`. Jeder Task committet auf `slice-02`; nach `main` kommt die Slice per `git merge --squash` als **ein** Commit (wie Slice 01). Git-Identität lokal `vompa`.

## Annahmen (bei Freigabe bestätigen)

1. **Sommerzeit-Flag = tzdb-Savings ≠ 0** (`ZonedDateTime.IsDaylightSavingTime()`). Erfüllt B-NOW-11 (Lord Howe, +00:30). Folge laut Probe: **Europe/Dublin** hat in der tzdb negative Sommerzeit → im Winter `is_dst: true` (Savings −01:00), im Sommer `false`. Das entspricht der Datenbank (irisches Recht: Sommerzeit ist die Normalzeit) und vermutlich dem Original (`bool(dst())`), widerspricht aber dem Alltagsverständnis. Alternative: `Savings > 0` → Dublin immer `false`. Empfehlung: tzdb-Verhalten, als Test festgehalten.
2. **Aliase sind gültig**, weil sie exakte tzdb-Schlüssel sind: `US/Eastern`, `GMT`, `Etc/UTC` (alle in `Tzdb.Ids`). Der Name kommt unverändert zurück (AC3), nicht der kanonische.
3. **Leerer oder fehlender Wert** (auch JSON `null`) → „Missing required argument“. **Nicht-String** (Zahl, Objekt, Boolean) → „Invalid timezone“ mit dem rohen JSON-Text als Wert. Leerzeichen-Namen (`" UTC"`) → „Invalid timezone“ (kein Trim).
4. **Textblock** = kompaktes JSON desselben Objekts, das in `structuredContent` steht (ein Serialisierungsvorgang).
5. **Fehlertexte** (fest, `{arg}` = Argumentname, `{value}` = Wert):
   - `Missing required argument: {arg}. Expected an IANA time zone name such as 'Europe/Vienna'.`
   - `Invalid timezone '{value}' in argument '{arg}'. Expected an exact IANA time zone name such as 'Europe/Vienna'; names are case-sensitive.`
6. `convert_time` bleibt in dieser Slice beim „not implemented“-Rumpf (Slice 03).

## Review Focus

1. Nicht-String-Werte für `timezone` (`42`, `true`, `{}`, `null`) → `isError`, kein JSON-RPC-Fehler, Server läuft weiter (Task 2, `NonStringTimezoneIsABusinessErrorAsync`).
2. Leerzeichen um gültige Namen (`" UTC"`, `"UTC "`) → „Invalid timezone“ mit dem Wert, kein stilles Trimmen (Task 1, Theory-Zeilen in `InvalidNamesAreRejected`).
3. Aliase (`US/Eastern`) werden akzeptiert und unverändert zurückgegeben (Task 1, `AliasIsAcceptedAndReturnedAsRequested`).
4. `structuredContent` passt zum veröffentlichten Ausgabeschema: genau die vier Pflichtfelder, snake_case, `is_dst` als JSON-Boolean (Task 2, `StructuredContentMatchesTheOutputSchemaAsync`).
5. Negative Sommerzeit (Europe/Dublin) → Verhalten laut Annahme 1, nicht zufällig (Task 1, `NegativeSavingsCountAsDaylightSavingTime`).
