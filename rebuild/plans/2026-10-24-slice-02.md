# Slice 02 "Time zones & current time" – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `get_current_time` returns the correct current time as `structuredContent` plus a JSON text block for every valid IANA time zone, and rejects missing, unknown and misspelled names and paths with `isError` and a clear text.

**Architecture:** `McpTime.Core` gets three types: `TimeZoneName` (exact match against `DateTimeZoneProviders.Tzdb.Ids`, D3/D4), `TimeResult` (result for an instant: ISO 8601 with offset to the second, English weekday, daylight saving time flag) and `CurrentTime` ("now" from `TimeProvider`, D13). `McpTime.Server` reads the argument raw (D10), builds business errors itself as `CallToolResult { IsError = true }` (D7) and serializes the result through a `JsonSerializerContext` with snake_case (D11). The host passes `TimeProvider.System`.

**Tech Stack:** .NET 10, NodaTime 3.3.6 (`Tzdb.Ids`, `Instant.InZone`, `ZonedDateTime.IsDaylightSavingTime()`, `OffsetDateTimePattern`), `ModelContextProtocol` 2.3.0, System.Text.Json source generator, xunit.v3, `FakeTimeProvider` (harness `FrozenClock` from slice 00).

**Spec:** `rebuild/slices/02-current-time.md`, `rebuild/PRD.md` F2 (AC1–AC5, unknown arguments), `rebuild/parity/business-cases.md` (B-NOW-1..15, B-ERR-1..5), `rebuild/parity/interface-cases.md` (I-RES-1, I-ERR-3, I-ERR-4), `rebuild/research.md` D3, D4, D7, D10, D11, D13, `CLAUDE.md`.

## Global Constraints

- Dependencies only Host → Server → Core; Core only NodaTime, no `TimeZoneInfo`, no MCP SDK, no `Console` (architecture tests); no new packages.
- "Now" only through `TimeProvider` – never `DateTime.Now`, `DateTimeOffset.UtcNow`, `SystemClock` (D13).
- A name is valid only if it is in `DateTimeZoneProviders.Tzdb.Ids` (ordinal); no normalization (no trim, no case folding) (D4, P3).
- Business errors only as a self-built `CallToolResult { IsError = true }`, never `McpException`/`McpProtocolException` (D7); error texts name the argument, the value and the expected format.
- JSON only through `JsonSerializerContext` (D11); result fields exactly `timezone`, `datetime`, `day_of_week`, `is_dst` (P2).
- ≤ 300 lines per file, one responsibility per class, no dead code, no TODO; `dotnet build -warnaserror` and `dotnet format --verify-no-changes` green.
- Microsoft C# naming: `Async` suffix, `_camelCase`/`s_camelCase`. Each task commits on `slice-02`; the slice reaches `main` as **one** commit through `git merge --squash` (as in slice 01). Git identity locally `vompa`.

## Assumptions (confirm on approval)

1. **Daylight saving time flag = tzdb savings ≠ 0** (`ZonedDateTime.IsDaylightSavingTime()`). Meets B-NOW-11 (Lord Howe, +00:30). Consequence according to the probe: **Europe/Dublin** has negative daylight saving time in tzdb → `is_dst: true` in winter (savings −01:00), `false` in summer. That matches the database (Irish law: daylight saving time is the standard time) and probably the original (`bool(dst())`), but contradicts everyday understanding. Alternative: `Savings > 0` → Dublin always `false`. Recommendation: tzdb behavior, recorded as a test.
2. **Aliases are valid**, because they are exact tzdb keys: `US/Eastern`, `GMT`, `Etc/UTC` (all in `Tzdb.Ids`). The name comes back unchanged (AC3), not the canonical one.
3. **Empty or missing value** (also JSON `null`) → "Missing required argument". **Non-string** (number, object, boolean) → "Invalid timezone" with the raw JSON text as the value. Names with spaces (`" UTC"`) → "Invalid timezone" (no trim).
4. **Text block** = compact JSON of the same object that is in `structuredContent` (one serialization pass).
5. **Error texts** (fixed, `{arg}` = argument name, `{value}` = value):
   - `Missing required argument: {arg}. Expected an IANA time zone name such as 'Europe/Vienna'.`
   - `Invalid timezone '{value}' in argument '{arg}'. Expected an exact IANA time zone name such as 'Europe/Vienna'; names are case-sensitive.`
6. `convert_time` keeps the "not implemented" body in this slice (slice 03).

## Review Focus

1. Non-string values for `timezone` (`42`, `true`, `{}`, `null`) → `isError`, no JSON-RPC error, server keeps running (task 2, `NonStringTimezoneIsABusinessErrorAsync`).
2. Spaces around valid names (`" UTC"`, `"UTC "`) → "Invalid timezone" with the value, no silent trimming (task 1, theory rows in `InvalidNamesAreRejected`).
3. Aliases (`US/Eastern`) are accepted and returned unchanged (task 1, `AliasIsAcceptedAndReturnedAsRequested`).
4. `structuredContent` matches the published output schema: exactly the four required fields, snake_case, `is_dst` as a JSON boolean (task 2, `StructuredContentMatchesTheOutputSchemaAsync`).
5. Negative daylight saving time (Europe/Dublin) → behavior according to assumption 1, not by chance (task 1, `NegativeSavingsCountAsDaylightSavingTime`).
