# Slice 04 "Start, local time zone & distribution" – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server starts with the detected local time zone or the one overridden with `--local-timezone`, rejects invalid values and unknown options before the transport starts, describes itself with `--help`, and can be packed as a `dotnet tool` and started with `dnx` (smoke test in CI).

**Architecture:** Only the host changes. `LocalTimeZone` (host) resolves the local zone: option value, otherwise system zone (`TimeZoneInfo.Local.Id`, Windows ID to IANA through ICU), otherwise `UTC` – the check always goes through `TimeZoneName.TryCreate` from Core (D4, D5). `ServerCommand` builds the root command with System.CommandLine; only after a successful check does `McpTimeHost` start the generic host with the stdio transport. The host no longer gets the command line (`Host.CreateApplicationBuilder()` without `args`); configuration only through environment variables. Packaging follows the template `dotnet new mcpserver` (D17), but framework-dependent.

**Tech Stack:** .NET 10, System.CommandLine 2.0.13, Microsoft.Extensions.Hosting 10.0.13, ModelContextProtocol 2.3.0, NodaTime 3.3.6 (only through Core), xunit.v3, `dotnet dnx`.

**Spec:** `rebuild/slices/04-cli-distribution.md`, `rebuild/PRD.md` F4 (AC1–AC4) and F1 AC5, `rebuild/parity/interface-cases.md` (I-LIST-6, I-CLI-1..3), `rebuild/research.md` D4, D5, D15, D16, D17, D18, `CLAUDE.md`.

## Assumptions (confirm on approval)

1. **Empty, spaces, `=`:** `--local-timezone ""` = not set (AC3) → detection. Only spaces (`" "`) = invalid value (error line). `--local-timezone=` and `--local-timezone` without a value are parse errors of System.CommandLine (probe: localized "a required argument is missing …" message, exit 1).
2. **Check as with the tools:** the same exact ordinal match (`TimeZoneName.TryCreate`), so `europe/vienna`, `W. Europe Standard Time`, `/etc/localtime` → error line.
3. **Detection (D5):** `LocalTimeZone.Detect(systemId, region)` – if `systemId` is exactly in tzdb → that one; otherwise `TimeZoneInfo.TryConvertWindowsIdToIanaId(systemId, region, out iana)` and, if there is no match, without region; if the result is in tzdb → that one; otherwise `UTC`. Input at run time: `TimeZoneInfo.Local.Id` and `RegionInfo.CurrentRegion.TwoLetterISORegionName`. The region turns `W. Europe Standard Time` in Austria into `Europe/Vienna` instead of `Europe/Berlin` (improvement over plain D5).
4. **Parse errors, unknown options, `--help`, `--version`:** default behavior of System.CommandLine 2.0 (probe): message in the UI language on stderr, help on stdout, exit 1; `--help` exit 0; `--version` prints `0.1.0`. This also applies to surplus arguments (`extra`) and a repeated option.
5. **Exit code** for an invalid time zone: `1` (like a parse error).
6. **Control characters in the value** are output as `\uXXXX` in the error line, so that it stays exactly one line (Review Focus 1).
7. **Tests of `LocalTimeZone`** are in `McpTime.Protocol.Tests/Host/` (the project already references the host) with `InternalsVisibleTo`; no new test project.
8. **Package:** framework-dependent `dotnet tool` (one package instead of 6 self-contained RID packages; `dnx` requires the .NET SDK anyway), `RollForward=Major`, `PackageId` **`Vompa.McpTime`** (free on nuget.org as of today), `ToolCommandName` `mcp-time`, `PackageType McpServer`, version from `Directory.Build.props` (`0.1.0`). `.mcp/server.json` with `name` **`io.github.vompa/mcp-time-net`**, `packageArguments` for `--local-timezone` (optional, named). Package README `src/McpTime.Host/README.md` (English, with `<!-- mcp-name: io.github.vompa/mcp-time-net -->`). No license metadata as long as the repo has no `LICENSE`.
9. **Smoke test in CI** (all three OSes, `shell: bash`): `dotnet pack src/McpTime.Host -c Release -o artifacts/package`, then `dotnet dnx Vompa.McpTime --source artifacts/package --yes -- --help` (exit 0, output contains `--local-timezone`) and with `--local-timezone Not/AZone` (exit ≠ 0). Fix the exact `dnx` syntax in task 3 by probing and record it in research.md. `artifacts/` in `.gitignore`.

## Review Focus

1. Value with a line break (`"Europe/Vienna\nX"`) → still exactly one line on stderr (task 2, `ControlCharactersStayOnOneLineAsync`).
2. Nearly valid values (`europe/vienna`, `W. Europe Standard Time`, `/etc/localtime`, `" "`) → error line, no start (task 1 `InvalidOverridesAreRejected`, task 2 `InvalidLocalTimeZoneEndsBeforeTransportAsync`).
3. Option given twice → exit ≠ 0, no start (task 2, `UnknownOrRepeatedOptionsAreRejectedAsync`).
4. System zone without an IANA equivalent (custom Windows zone, nonsense, `""`) → `UTC`, no crash (task 1, `UnmappableSystemZoneFallsBackToUtc`).
5. Tool snapshot does not depend on the machine's zone: the harness starts with `--local-timezone UTC` by default (task 2, existing `ToolsListSnapshotAsync` stays green on every machine).
